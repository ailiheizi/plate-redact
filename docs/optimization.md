## 1. 版本演进：每个版本换掉了什么

| 版本 | 做法 | 实测结果 | 结论 |
| --- | --- | --- | --- |
| v7 平衡版 | 开放词表检测（阈值 0.20）主检测 + 低频辅助检测 + 车辆门控 + 单次 2× 放大补检（阈值 0.25）+ 框大小过滤 + 外扩 0.30 | 见下方「过度打码」一行 | 历史实验，非当前证据 |
| v7 时间驱动版 | 补检从「空间盲扫所有近景车」改成「只补该车前后 8 帧检出过牌、当前帧漏」的帧 | 见下方「补检」一行 | 当时最优 |
| v9b / v12 | 单检测器 + OCR 只做确认层；v12 删掉两套补充引擎、主阈值降到 0.15 | 见下方「单引擎对照」一行 | 当时认为「检测器只一个，其他引擎做验证不并集」 |
| v10 车为中心 | 车辆轨迹作载体、建 tag 即打先验带、锚点×车框外推 | 见下方「车为中心」一行 | 方向对，但 track 碎片化未解决 → 停用 |
| 现行 | 多引擎并集 + 时序冗余 | — | **与早期实验结论相反** |

### 单引擎对照（v9fix2 与 v12）

| 指标 | v12（单检测器 + OCR 确认层） | v9fix2 | 测什么 / 样本 / 状态 |
| --- | --- | --- | --- |
| 卡车模糊牌 | 57% | 56% | 同一基准片的覆盖 / 历史实验 |
| 蓝牌 | 67% | 65% | 同上 |
| 左侧贴边小牌 | 83% | 82% | 同上 |
| 整车误检帧 | 0 | 0 | 同上 |
| 打码面积 | 0.7% | 0.5% | 同上 |
| 大块帧（>5000 px） | 4 | 18 | 同上 |

当时的归因很具体：**大框 / 整车误遮的元凶是并集里的两套补充引擎，不是开放词表检测器**。
出现过 376×124 的块（宽高比 3.04，而真车牌约 3.14）——这是检测器把**车尾大矩形**
当成「大号车牌」的**尺度歧义**。删掉补充引擎后，大块帧从 18 → 4、整车误检 0，
而开放词表检测器的框实测定位很准。

> 但这条结论后来被推翻了：现行口径回到了**多引擎并集**。
> 现在的解释是「并集的代价是这类语义误报，需要一层消误报」，而不是「取消并集」。
> **两条路都跑过、并且写下为什么换**，这一层记录的价值就在这里。

## 2. 四个最小复现与修复（轻量多引擎链）

源项目对轻量实验链做过四个最小检查，每个都证明「代码路径**可以**造成候选损失或覆盖不足」——
不等于已经测得真实视频里的发生率。

| 检查 | 方法 | 结果 |
| --- | --- | --- |
| 车辆门控 | 从脚本提取函数；分数 0.40、车辆检测为空 | **候选被删除** |
| 遮挡去重 | 两个扩张 mask 的 IoU 为 0.485714，第二个原始候选部分超出第一个 mask | 第二个 mask 被丢弃，**第二候选只被覆盖 70%** |
| ONNX 尺寸 | 模拟 session 分别传 `imgsz=640` / `1920`，另读 ONNX 图结构 | 两次预处理**都是 640×640**，模型也是固定 640×640 |
| OCR 门槛 | 模拟 1 个检测分数 0.95 的有效候选 + 3 字符 OCR 结果 | 流水线返回 **0 个候选** |

对应的实施修复（测什么 = 覆盖与候选保留；样本 = 合成用例 + 回归；状态 = 已实现并有回归）：

- 按**向外取整后的实际像素**计算矩形并集与未覆盖区域；保留分离的精确框，
  **不生成包住多个车牌的整车大矩形**；
- 多引擎观测只去掉**坐标完全相同**的重复项；预测框不再被重叠的观测框直接丢弃；
- 通过几何筛选后的最终 mask，**只有在全部像素已被其他 mask 覆盖时**才可省略；
- 重叠填充的平均色**统一从当前原始解码帧取样**；
- 时间补洞的「三帧支持」改为**三个不同帧号**——同一帧里的多个引擎或视图**不能重复计票**；
- 计划生成器不再用**浮点匹配容差**去掉覆盖边界不同的最终框；
  `restoration_coverage` 对每一项删除 / 替换**单独计算露出的像素区域**；
- 旧修正格式没有可信的逐牌恢复裁决，因此删除大框后露出的车身 / 背景像素也可能被标为 `UNKNOWN`，
  **不会自动判定为安全或把大框补回**；此时只保存 `NEEDS_REVIEW` 的 JSON 并返回退出码 2；
- 修正渲染器在**创建任何视频输出之前**独立重算该检查，历史计划同样适用；
  改缓存里的 `status` / `restoration_coverage` **不能**绕过实际区域检查。

| 数字 | 测什么 | 样本 | 状态 |
| --- | --- | --- | --- |
| 19 项新增回归 | 覆盖保护修复的测试覆盖 | 重叠露字、相邻框一像素空洞、浮点边界、同帧多车、旧计划与伪造缓存状态、输出创建前阻断、模拟检测器驱动完整入口 | 已实现 |
| 150 组随机矩形 | 并集 / 差集对照独立像素栅格计算 | 随机矩形 | 已通过 |
| 70% → 完整覆盖 | 合成重叠案例中第二候选的覆盖率 | 1 个合成案例 | 修复后；框外像素保持不变 |
| 1327 项 / 595 帧 | 一份历史修正计划里的删除 / 替换数 | 只读检查 | 均有恢复源像素 → 新渲染门禁**会阻断**直接使用 |

> **必须标注的边界**：1327 / 595 这个统计**包含移除错误大框时恢复的车身和背景**，
> **不是 595 帧已确认漏牌，也不是 1327 个真实车牌**。

## 3. 增强视图（enhanced profile）：三轮，仍未默认开启

第二轮在**同一份开发集**（90 个采样帧、133 个几何框）上逐帧重算基线并断言结果完全一致：

| 配置（均含 baseline） | IoU ≥ 0.50 | 完整整数牌区覆盖 | mask 像素 | 90 帧额外耗时 |
| --- | --- | --- | --- | --- |
| baseline | 125/133 | 124/133 | 358,442 | 冻结基线 |
| 车辆 ROI（识别引擎 raw 框） | 126/133 | 125/133 | 367,766 | +17.25 s |
| 640 切片（请求 1280 输入） | 125/133 | 124/133 | 375,500 | +51.49 s |
| enhanced = baseline + 切片 + 车辆 ROI | **126/133** | **125/133** | **384,744** | 两组增量之和 |

- 第二轮单独可见的 ROI 增益有 **1 处**；切片在与 ROI 合并时**没有额外覆盖**；
  把首轮切片候选也算进完整并集时，开发集上共 **3 处**几何匹配增益；
- **全部是开发集几何匹配，不是确认的可读漏牌**；6 个未完全覆盖的 GT 仍未解决；
- 代价：mask 像素 **+约 26%**，以及 ROI / 切片的计算；
- 代表帧的**源像素只读核对**发现新增切片候选**并非都可视为精确牌区**：
  一处覆盖车辆后部大块（真实牌区只是其中小区域），一处落在路侧设施 / 广告附近；
- 阈值重放显示：把新增切片阈值统一抬到 0.25 **会丢失一处增益**——
  不建议用单一阈值换表面框数下降；
- 第三轮加了**通用车辆相对几何过滤**：只作用于 supplemental 候选，不改变 baseline；
  候选需落在已检出车辆的扩展范围内，且宽 / 高 / 面积分别不超过车辆对应尺寸的保守比例；
  被拒绝的候选仍写入 `geometry_rejections` 便于复核，
  **不能被当作「没有车牌」的负证据**；无车辆上下文时**不静默删除**。
  轻量多视图相关测试 **17/17 通过**，但**尚未在完整真实视频上重新统计召回**。

**默认建议**：`enhanced` 只作 `CANDIDATE_ONLY` 实验开关，**默认仍为 baseline**；
启用前应在隔离的完整视频上检查非牌区误遮面积、车辆轨迹 `UNKNOWN`、编码后复检和音视频帧数。

## 4. 可复用的经验（踩过的坑）

- **补检要时间驱动**（有历史才补），不要空间盲扫；
- **过滤候选与多打一块的代价不对称**：漏打是隐私事故，多打只是一块色块。
  所以候选过滤一律关闭，车辆检测只用于「多打一块」；
- **几何 / 正则过滤要针对倾斜牌留裕量**。早期按正视角标准设的过滤把倾斜牌、
  贴边牌和短车牌误杀（宽高比、贴边竖条、号码长度都出过误杀），放宽后才不再暴露；
- **不要用 OCR 文本 / 车牌格式当过滤依据**：低置信识别文本经常是错的，
  **位置一致性比文本格式可靠**；
- **通用 OCR 兜底在运动视频上不可行**：对模糊帧识别出的文字极少、命中车牌为 0，
  只在静止清晰画面（如停车监控）有效。模糊才是根因；
- **提前打码的正确实现是「跟踪缓存沿用」**，不是指望 OCR 去读模糊图像；
- **打码残留久一点比提前消失好**（用户明确要求）；
- 不要复用旧日志判断结果（曾有旧日志误导判断）。

## 5. 编码噪声与质检口径

- 输出用高质量 H.264 编码，而不是旧的 `mp4v`（画质与兼容性都更好）；
- **重编码会造成全帧像素级差异**（源项目记录过「diff>5 达 80%」），
  所以质检**不能用低阈值像素对比**，要用高阈值 + 大块连通域判定；
- 本项目的做法更简单也更可靠：**只检查「计划框在成品里是不是近似纯色」**
  （逐通道标准差上限，留视频编码噪声余量），以及帧链是否可重现。
  这样编码误差不会被当成错位，mask 区域的合法变化也不会被误判。
- 已知工程陷阱：质检脚本帧索引与处理流程可能差 1 帧（0-indexed vs 1-indexed）；
  **内存不足时推理速度可下降约 10 倍**，先查内存再判性能；
  某些平台对用户文档目录有额外权限门禁，被拒时需要用户授权；
  OpenCV 的 VideoWriter 写中文文件名会失败，需用英文路径输出后重命名。

## 6. 端侧与量化约束

- 部署包**只放轻量检测器 + 跟踪 / 时序模块**，教师全部留在离线；
- **砍掉 OCR**：打码只需要定位；
- 量化优先 **w8a32 / w8a16**（int8 权重 + 高精度激活）：
  权重 int8 对召回影响小、**激活 int8 会明显掉召回**；
- **校准集必须含真实车牌场景**（远距 / 模糊 / 夜间），否则 int8 会崩——
  源项目记录过一例校准不当后的检测指标从 0.61 掉到 0.32
  （测什么 = 量化后检测指标；样本 = 未记录；状态 = 历史记录，**本仓库没有复现**）；
- **低频检测 + 跟踪补间**：检测降到 1–5 Hz，中间帧用轨迹预测车牌框；
  两遍法弥补低频检测的漏检；配温度阈值做降频保护。
- 训练路线（用于解决坐标偏差与域不匹配）：自动标注（优于 VLM 直接标）+ 跟踪器多帧聚合收紧框；
  小样本人工精标 **200–800 帧**做干净验证集（**训练可以脏，验证必须干净**）；
  合成渲染车牌补「人眼可读但检测难」；box jitter 抗噪声、RepGT loss 防框不包全、
  车-牌空间关系 loss；打码框外扩 5–15% 做安全边际。

> 本节是**设计约束**。端侧实机的实际帧率与功耗**未测**，拿到实机前不作声明。

## 7. 模型替换与许可边界

### YOLO12n / RT-DETR-L（只做到冒烟）

| 数字 | 测什么 | 样本 | 状态 |
| --- | --- | --- | --- |
| `PASS_SHAPE_ONLY`，输出 `[117,6]` / `[300,6]` | 权重可加载 + 640 输入 shape check | 各 1 次 | 已跑 |
| 5 epoch smoke 未完成 | 训练可行性 | CPU，batch 16 首批约 73 秒；另一次 batch 4 约完成 1 个 epoch 后中止 | `INTERRUPTED`，未采用部分 checkpoint |
| 50 epoch 公平实验 `NOT_STARTED` | 模型优选 | — | **没有生成任何 mAP / 召回结论** |
| 8 帧抽样：car×8 / car×26+truck×12 | 通用权重输出类别 | 8 帧（每 30 帧取 1） | 能枚举车辆，**不是车牌检测器** |

**数据不足，不构成结论**；它们最多算待补资源的研究候选。

### YOLOX-Nano（可审查的替换路线，仍在实验）

- 目标是把默认权重替换为**可审查、可离线部署**的 ONNX 方案。代码仓库为 Apache-2.0，
  **本地训练权重必须自有或另行取得授权**；ONNX 只是部署格式，
  **不改变原权重、代码或数据集的许可**；
- 训练初始化 = Apache-2.0 预训练骨干 + 本地一类车牌头，10 epoch；
- ONNX 形状：输入 `[1,3,640,640]`、输出 `[1,8400,6]`，使用外部 `.onnx.data`；
- 4K 冒烟：3840×2160、30 fps、**1800/1800 帧完整解码**、2218 个遮挡框、
  **无人工关键帧补偿**；但 `conf=0.01` 下视觉抽查发现**车身大块误检** →
  该文件是候选，**不是交付视频**；
- 独立 120 张测试图 / 219 个框上，`conf=0.01`、IoU ≥ 0.5 的简单匹配召回约 **72.6%**
  （旧 10 epoch 权重；**不是全片隐私召回率**，也不证明可替代现有权重）；
- 后续门禁：用人工 Gold 继续训练（建议至少 50–100 epoch）；
  用**相同输入、阈值、ROI、时序和后审计**做对比；任一 `UNKNOWN` 或审计不完整只生成 draft；
  在目标设备上实测 ONNX→NPU 工具链；**未有实机前不能宣称帧率、算力或功耗**；
  商用发布前逐项核对权重、训练数据、各引擎、OpenCV、ONNX Runtime 与设备端推理工具链的许可。

### 许可与加载器约束

- **代码许可 ≠ 权重许可 ≠ 数据许可**。仓库 LICENSE 不自动覆盖现实图像权利；
- 分割 / 时序教师的替代方案里，**模型与 checkpoint 是 Apache-2.0，而实际调用的推理框架是 AGPL-3.0**——
  闭源硬件商业交付前应取得相应商业许可，或把时序教师迁移到官方 Apache-2.0 实现；
- 有模型的权重**需要人工授权**（不自动下载）；缺少合法本地权重时必须产生
  `blocked_missing_model` 报告，**严禁自动下载或以阴性补齐评测**；
- 一个具体的加载器陷阱：某推理框架**只按 checkpoint 文件名判断架构**，
  而冻结副本会被命名为通用名（如 `model.pt`）。探针必须从**哈希绑定的原始文件名**
  严格解析架构白名单，再让对应 builder 读取同一私有冻结副本；
  未知或重命名的 checkpoint **继续 fail-closed**，且不得绕过 `O_NOFOLLOW`、
  冻结哈希、只读快照或精确清理。
