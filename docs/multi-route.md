# 多重路线

同一个环节都留了不止一条路。下面按环节列，并标出哪些实测过、结论是什么。

## 1. 候选生成（并行取并集）

| 路线 | 作用 | 代价 |
| --- | --- | --- |
| 全帧低阈值 | 兜底，宁可多检 | 误报上升 |
| 重叠切片（2×2 / 640） | 补远距小目标 | 时间与误遮 |
| 逐车辆 ROI 放大 | 补小牌、暗牌 | 依赖车辆枚举质量 |
| 两轮车窄条兜底 | 补摩托 / 电动车窄牌 | 只是缓解，不算已证实 |
| 多引擎并集 | 覆盖各引擎的系统性盲区 | 算力 |

取舍是明确的：**用算力换召回**。配套约束是「任一补充引擎不可被静默关闭」。

## 2. 复核（两条独立审计 + 三档队列）

- **车牌审计**：计划框在成品里是否真的成了纯色；
- **车辆覆盖审计**：每条车辆轨迹是否有可解释牌区；
- **队列优先级**：P0 计划外残留 / 疑可读 → P1 车辆无可解释牌区 → P2 普通分歧。

机器判不了的一律留 UNKNOWN 交真人，不靠「分数高就放行」。

## 3. 架构分叉（真跑过，结论相反）

| 版本 | 方案 | 实测结论 |
| --- | --- | --- |
| v9b / v12 | 单检测器 + OCR 只做确认层 | 曾是最优；v12 删掉两套补充引擎、主阈值降到 0.15 |
| v10 | 车为中心、先建 tag 即打先验带 | **更差**：轨迹碎片化——贴边小牌覆盖 0%、打码面积 2.2%、整车误检 1（对照 82% / 0.5% / 0） |
| 现行 | 多引擎并集 + 时序冗余 | 回到并集路线，**与早期实验结论相反** |

两次分叉的具体数字：

- **单引擎 vs 并集**（同一基准片，历史实验）：卡车模糊牌 57% vs 56%、蓝牌 67% vs 65%、
  左侧贴边小牌 83% vs 82%、整车误检 0 vs 0、打码面积 0.7% vs 0.5%、
  大块帧（>5000 px）**4 vs 18**。当时的归因很明确：**大框的元凶是并集里的两套补充引擎**
  （出现过宽高比 3.04 的 376×124 块，而真车牌约 3.14——检测器把车尾大矩形当成"大号车牌"的
  **尺度歧义**），不是开放词表检测器。
- **车为中心**：400 帧里 154 个 tag 对应实际约 15 辆车，154 个 tag **只有 24 个完成确认**；
  确认率一低，贴边车的先验带就覆盖不到。**根因是关联质量，不是方向**。

这一层的价值不在「最后选了哪个」，而在**两条路都跑过，并且写下来为什么换**——
现在的解释是「并集的代价是语义误报，需要一层消误报」，而不是「取消并集」。

## 4. 模型替换

- YOLO12n / RT-DETR-L：只做到 shape 冒烟（输出 `[117,6]` / `[300,6]`，`PASS_SHAPE_ONLY`），
  5 epoch smoke 因 CPU 预算不足中断，50 epoch 公平实验 `NOT_STARTED` —— **数据不足，不构成结论**；
  通用 COCO 权重在 8 帧抽样里输出的是 car / truck，**不是车牌检测器**；
- YOLOX-Nano ONNX：**可做许可证审查的替换路线**，仍在实验。4K 冒烟 3840×2160 / 1800 帧完整解码、
  2218 个遮挡框、无人工补偿，但 `conf=0.01` 下抽查发现**车身大块误检** → 候选不是成品；
  独立 120 张测试图 / 219 个框上简单匹配召回约 **72.6%**（旧权重，且不是全片隐私召回率）。
  代码 Apache-2.0，但**本地训练权重必须自有或另行授权**；ONNX 只是格式，不改变许可；
- SAM3 → SAM2.1：授权阻塞后的替代。**代码与 checkpoint 是 Apache-2.0，
  但实际调用的推理框架是 AGPL-3.0** —— 闭源商业交付前要取得商业许可或迁移到官方实现。

## 5. 明确不做

全帧切片提分辨率、为 RL 换检测器、把世界模型当检测器、像素级无证据外推。

## 6. 增强视图（增强 ≠ 默认开启）

候选生成里还有一条**实测过但没默认开启**的路线：把普通重叠切片和车辆扩边 ROI
作为 supplemental 候选并入 baseline（`enhanced` profile）。

- 在同一份 90 帧 / 133 框开发集上：baseline 125/133（IoU ≥ 0.50）、完整整数牌区覆盖 124/133；
  加上车辆 ROI 后 126/133、125/133；`enhanced` 合并后 126/133、125/133；
- 代价是 mask 像素 **+约 26%** 以及 ROI / 切片计算；
- 代表帧的**源像素只读核对**发现新增切片候选并非都可视为精确牌区：
  一处覆盖车辆后部大块（真实牌区只是其中小区域），一处落在路侧设施 / 广告附近；
- 第三轮加了通用**车辆相对几何过滤**（只作用于 supplemental 候选，不改变 baseline），
  被拒候选写入 `geometry_rejections`，**不能被当作"没有车牌"的负证据**。

结论：`enhanced` 只作 `CANDIDATE_ONLY` 实验开关，**默认仍为 baseline**；
启用前应在隔离的完整视频上检查非牌区误遮面积、车辆轨迹 `UNKNOWN`、编码后复检和音视频帧数。
完整数字见 [工程约束与优化记录](optimization.md#3-增强视图enhanced-profile三轮仍未默认开启)。
